# スコープ境界と数値パラメータ

判断に迷ったときの基準を集約する。
ここが「含める／含めない」と「どこで値を持つか」の正である。

## MVPに含めないもの

実装中に要望が出た場合も、Phase 4完了までは着手しない。

- ユーザー登録、サーバー、データベース
- マルチプレイ、ランキング、課金
- 自由移動を伴う本格RPG、複雑な戦闘システム
- リアルタイムの大相撲情報
- 音響演出（ON/OFF付きで将来追加）
- 決まり手82手、歴史編・文化編、デイリークイズ、称号・実績

出典は `../sumo-quest-prd.md` の「14. MVPスコープ」と「19. 将来拡張」。
判断が割れた場合はPRDを正とする。

## 数値パラメータの扱い

EXP配分、番付の必要累積EXP、合格率は**設計書時点では仮の値**である。
ハードコードせず、以下の場所に持たせる。

| パラメータ | 保持場所 |
|---|---|
| 合格率 | ステージデータの `Stage.passRate` |
| 学習・クイズのEXP | 各データの `rewardExp` |
| ステージクリアEXP | `Stage.clearRewardExp` |
| 番付の必要累積EXP | `src/data/ranks.ts` |

**具体的な数値は本書に転記しない。**
設計書「7. ゲーム進行ルール」と実装データが正であり、
二重管理すると片方だけ更新されて食い違う。

## 調整のタイミング

Phase 3完了時点（P3-6）で通しプレイを行い、昇進テンポとプレイ時間を見て調整する。

この調整が**コード変更を伴わないこと**は、Phase 2の完了ゲートで担保する。
コード変更が必要になった場合、データ駆動化が実際には完了していない。
