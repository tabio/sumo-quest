# テストの投入計画

テストを最後にまとめず、以下のタイミングで積む。

各行の「対象」は、そのフェーズの完了ゲートに含まれる。

## 投入タイミング

| 種類 | 投入時期 | 対象 |
|---|---|---|
| 単体 | Phase 1前半（P1-1〜P1-6と同時） | 下記「単体テスト」 |
| コンポーネント | Phase 1後半〜Phase 2 | 下記「コンポーネントテスト」 |
| E2E（1本目） | Phase 1完了ゲート | 新規開始→STAGE 1クリア |
| E2E（残り） | Phase 3〜4（P4-9） | 下記「E2Eテスト」の2〜6 |
| コンテンツ検証 | Phase 2（P2-12、STAGE 2追加と同時） | 下記「コンテンツ確認」 |

## 単体テスト

画面がなくても検証できる。後から書こうとすると必ず後回しになるため、実装と同時に書く。

- 累積EXPから番付を算出する
- 横綱条件を判定する（EXPだけでは昇進しない）
- ステージを順番に解放する
- 初回報酬の二重取得を防ぐ
- セーブデータの検証・移行
- クイズ合格率の境界値

## コンポーネントテスト

- 選択肢をキーボードとタッチで選べる
- 回答後に解説が表示される
- 未解放地点が操作できない
- セーブ有無で「つづきから」の状態が変わる

## E2Eテスト

1. 新規開始からSTAGE 1クリアまで
2. 再読み込み後の続きから
3. 全6ステージと横綱到達
4. 不正解から再挑戦
5. モバイル表示
6. GitHub Pagesのサブパス配信

**1本目をPhase 1の完了条件に含める。**
Phase 2の汎用化リファクタでSTAGE 1が壊れたことを、即座に検知するため。

## コンテンツ確認

機械検証できるものは、ビルド時に失敗させる（P2-12）。

| 項目 | 検証方法 |
|---|---|
| 問題に正解が一つだけあること | 機械検証 |
| 参照先IDが存在すること（技・用語・NPC） | 機械検証 |
| 相撲用語と説明の正確性 | 人手（P4-10） |
| 誤答解説が誤解を生まないこと | 人手（P4-10） |
| 小学生にも読める文章量と表現 | 人手（P4-10） |
