# ADR-0001: 実行計画をフェーズ単位に分割する

状態: 採用
日付: 2026-08-29

## 背景

実行計画を単一ファイル `docs/sumo-quest-execution-plan.md`（262行）として作成した。

その後、複数の作業を並行して進める方針が決まった。
このままでは、全フェーズの担当者が同一ファイルを同時に編集することになる。

特に問題になるのは次の3点。

- タスクの状態更新が全員同じファイルに集中する
- 番号付き見出しのため、節をひとつ挿入すると以降がすべてずれる
- 進捗表を中央に持つと、更新のたびに衝突する

## 決定

実行計画を `docs/plans/` へ移し、フェーズごとのファイルに分割する。
あわせて `CONVENTIONS.md` に文書の運用規約を定める。

主要な規約は次のとおり。

- 1ファイル1オーナー
- 進捗を中央に集約しない
- 見出しに番号を振らない
- 安定ID（`P1-3`、`R-2`、`ADR-0001`）で相互参照する
- 表は末尾に追記し、並べ替えない
- 1文1行で書く
- 同じ事実を2箇所に書かない
- 決定は `decisions/` への追記のみで記録する

## 理由

コンフリクトには、Gitが検知する行の衝突と、検知されない意味的な不整合の2種類がある。

ファイル分割は前者にのみ効く。
後者（同じ数値が2箇所にあり片方だけ更新される）はマージが成功してしまうため、
「同じ事実を2箇所に書かない」を規約として明示する必要がある。

見出し番号の廃止と1文1行は、それ自体は小さな工夫だが、
テキストの衝突確率を実際に下げるうえ、コストがほぼゼロである。

## 影響

- `docs/sumo-quest-execution-plan.md` は削除し、`docs/plans/` に置き換える
- `docs/sumo-quest-prd.md` と `docs/sumo-quest-design.md` は**変更しない**（冒頭に関連文書へのリンクのみ追加）
- 以降、設計書やPRDを書き換えたくなった場合は、原則として本ディレクトリにADRを追加する

## 検討した代替案

### 単一ファイルのまま運用する

分割しない場合、フェーズをまたぐ参照が読みやすいという利点はある。
しかし並行作業では状態更新が集中し、衝突が常態化するため採用しない。

### PRDと設計書にも番号なし見出しを適用する

一貫性の面では望ましいが、全行を書き換えることになる。
移行中のブランチとの衝突がかえって大きくなるため、既存2文書は番号付きのまま凍結する。
