# ADR-0005: E2Eは配信と同じ basePath の下で out/ を配信する

状態: 採用
日付: 2026-08-29

## 背景

E2E 1本目（P1-E2E）は、静的エクスポートした `out/` を `serve` で配信して実行する。
配信先はポート直下（`http://127.0.0.1:4173/`）とし、テストは `page.goto("/")` で開いていた。

これはローカルでは通るが、CIでは5本すべてが失敗した。

`basePath` は GitHub Actions 上でのみ `/sumo-quest` になる（[R-1](../risks.md) 対策）。
一方、`out/` の中身はサイトのルート相当で、`basePath` はリンクと資産のパスにだけ付く。

そのためCIでは次の食い違いが起きる。

| 対象 | 実際の配信先 | HTMLが指すパス |
|---|---|---|
| ページ | `/` | `/sumo-quest/` |
| JS・CSS | `/_next/...` | `/sumo-quest/_next/...` |

JSが404になるとハイドレーションが起きない。
画面はいずれもクライアント側で描画されるため、事前生成されたHTMLには `<h1>` すら含まれず、
全テストが「要素が見つからない」で失敗していた。

`basePath` の導出は `next.config.ts` にのみあり、配信側は参照していなかった。

## 決定

**E2Eも配信と同じ `basePath` の下で `out/` を配信する。**

- `basePath` の導出を `config/basePath.mjs` に集約し、`next.config.ts` と
  `playwright.config.ts` および `scripts/serve-e2e.mjs` が同じ値を使う
- `scripts/serve-e2e.mjs` が `out/` を一時領域の `basePath` 配下へ写してから配信する
- `baseURL` に `basePath` を含め、テストの `goto` は baseURL からの相対パスで書く
- `webServer` の待機はポートではなくURLで行う

## 理由

`basePath` を外してE2E専用のビルドを作る案もあるが、それでは
[R-1](../risks.md)（サブパスでリンク・画像が壊れる）をE2Eが素通りする。
今回まさにその壊れ方をCIが検知したのであり、検知しなくする方向へ倒すべきではない。

配信と同じ形にすれば、[testing.md](../testing.md) のE2E 6「GitHub Pagesのサブパス配信」の
経路を1本目の時点から通すことになる。

導出を1箇所に集約するのは、ビルドと配信で別々に持つと、
片方だけ更新されてもテストが通ってしまうためである。

`config/basePath.mjs` を TypeScript ではなく `.mjs` で置いたのは、
`scripts/` 配下のスクリプトを Node がそのまま実行できるようにするためである。

URLで待機するのは、`basePath` 配下へ置けていない場合に、
個々のテストの失敗ではなく起動時点で気づけるようにするためである。

## 影響

- テスト内の `goto` は先頭スラッシュで書けない。書くと `basePath` を外れて404になる
- `basePath` の値を変える場合は `config/basePath.mjs` だけを直す
- CIでは失敗時に `playwright-report/` が成果物として残る（HTMLレポーターを追加した）

## 検討した代替案

### E2Eのときだけ basePath を無効にしてビルドする

配信の準備が不要になり、テストも `/` のまま書ける。
しかしサブパス配信での破損をE2Eが検知しなくなる。R-1 の対策を弱めるため採らない。

### `serve` のリライト設定でサブパスを吸収する

写す処理が不要になる。
しかし配信されるファイルの位置が本番と異なり、
リライト設定自体の誤りをE2Eでは検知できない。

### テスト側で `basePath` を連結したパスを組み立てる

`baseURL` をポート直下のままにできる。
しかし `goto` のたびに連結を書くことになり、書き忘れた1箇所だけが
ローカルで通ってCIで落ちる。今回と同じ壊れ方を残す。
