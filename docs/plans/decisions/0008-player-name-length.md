# ADR-0008: プレイヤー名の上限を10文字とし、保存検証でも見る

状態: 採用
日付: 2026-08-29

## 背景

プレイヤー名の規則は設計書「6.2 名前入力」で「1〜12文字」と定めている。
入力欄（`src/app/new-game/page.tsx`）と `src/lib/playerName.ts` はこの値を実装している。

一方、localStorage から読み込んだセーブの検証（`src/lib/validation.ts` の `isPlayerSave`）は、
`playerName` について文字列であることしか確かめていなかった。

そのため localStorage を直接書き換えれば、任意の長さの名前がそのまま読み込まれ、
ステータス画面やエンディングに描画される。
入力側が守っている不変条件が、保存側では守られていない状態だった。

同一オリジンからの操作が前提であり、影響もレイアウトの崩れに留まる。
値は React の JSX 補間で描画されるため、注入の経路にはならない。

## 決定

**上限を10文字とし、入力欄と保存検証の双方で検証する。**

- `PLAYER_NAME_MAX_LENGTH` を 12 から 10 に変更する
- 上限の値は `src/lib/playerName.ts` の定数を唯一の出所とする
- `isPlayerSave` はこの定数を参照して `playerName` の長さを検証する
- 数え方は入力側に合わせ、サロゲートペアを1文字として数える

## 理由

上限を10文字にしたのは、しこ名として十分な長さでありながら、
狭い画面（320px）でステータス欄や取組の表示が折り返しにくくなるためである。

保存検証を入力側と同じ上限にしたのは、片方だけを厳しくすると壊れるからである。
入力を12文字のまま保存検証を10文字にすると、入力欄が受け付けた名前が
次回の読み込みで `invalidShape` となり、セーブが破損扱いで読めなくなる。
入力と保存は同じ不変条件を持たなければならない。

長さの数え方を `[...name].length` としたのは、入力側が同じ数え方をしているためである。
UTF-16 の長さで数えると、入力欄を通った絵文字入りの名前を読み込み側が弾く。

検証に失敗した場合の扱いは既存の方針を変えない。
破損とみなして削除せず、理由を返してタイトルで復旧を案内する（設計書「16. エラー・例外設計」）。

## 影響

- 設計書「6.2 名前入力」の「1〜12文字」は、上限について本ADRが置き換える
- `docs/plans/phase-1-vertical-slice.md` の P1-8 の完了条件も同様に、上限は本ADRを正とする
- 11〜12文字の名前を持つ既存セーブは、読み込み時に破損として扱われる。
  配信前であり該当する利用者はいない
- `isPlayerSave` の検証項目が1つ増える
- `src/lib/validation.ts` が `src/lib/playerName.ts` に依存する

## 検討した代替案

### 上限を12文字のまま、保存検証だけを追加する

設計書を変えずに済み、既存セーブも全て読める。
しかし今回は表示幅の観点から上限そのものを見直す判断をしたため、採用しない。

### 保存検証で上限を超える名前を切り詰める

セーブを読めなくせずに済む。
しかし利用者が意図しない形で保存データを書き換えることになり、
「破損しても消さない・変えない」という既存の方針と矛盾する。

### 入力欄に `maxLength` 属性を付けて防ぐ

入力の時点で超過を防げる。
しかしこれは表示上の補助にすぎず、localStorage の直接書き換えには効かない。
検証の代わりにはならない。
