# ADR-0008: 学習と取組の途中に、確認つきの離脱導線を置く

状態: 採用
日付: 2026-08-29

## 背景

学習（`/stage/[stageId]`）と取組（`/battle/[stageId]`）には、途中で抜ける導線がない。

学習の導線は最後のメッセージまで読んだあとにしか現れず、
取組の導線は全問に答えてリザルトへ移るまで現れない。

そのため、ステージに入ったあとで「今日はここまでにする」「図鑑を見たい」と思っても、
ブラウザの戻る操作以外に画面を離れる方法がない。

設計書「5. 画面遷移」の図も、マップ→学習→取組→リザルトの一方向しか描いておらず、
途中で抜ける経路を定めていない。

## 決定

**学習と取組の画面に、確認を挟む離脱導線 `StageExit` を置く。**

- 画面の先頭に「やめる」を右寄せで出す
- 押すと確認ウィンドウを開き、失われるものと残るものを文言で示す
- 確認から「タイトルへもどる」「マップへもどる」「つづける」を選べる

行き先を2つ出すのは、やめる理由が2種類あるためである。
遊ぶのをやめるならタイトル、別の場所へ行くならマップになる。

失われるのは、その画面で進めた分（読みかけの稽古、答えた分の取組）だけとする。
番付・EXP・おぼえた技と用語は、すでに保存済みのため残る。
確認ウィンドウでこの2つを分けて伝える。

## 理由

### なぜ確認を挟むか

「やめる」は取り消せない。
取組を数問答えたあとに押し間違えると、その分をやり直すことになる。

進む導線（「つぎへ」「けっかへ」）と同じ画面に並ぶため、
確認なしでは押し間違いがそのまま離脱になる。

### なぜ画面の先頭に置くか

見つからない導線は無いのと同じである。
取組では解説ウィンドウの分だけ画面下端が動くため、下部に置くと位置が定まらない。

主たる導線ではないため、右寄せの副次ボタンに留め、稽古と取組の手前に立ちはだからないようにする。

### なぜ押したボタンを消さないか

確認を開いたときに押した要素が消えると、フォーカスが `body` に落ち、
キーボード操作では今どこにいるのかを見失う（設計書「15.」）。

「やめる」は開閉のトグルとして残し、`aria-expanded` で状態を伝える。

## 影響

- `src/components/game/StageExit.tsx` を追加する
- `StageScreen` と `BattleScreen` が、それぞれの文言でこれを描画する
- 設計書「5. 画面遷移」の一方向の図に、学習と取組からの離脱経路が加わる
- 設計書「6.4 学習」「6.5 取組」の画面要素に、離脱導線が加わる
- 進行ルールは変えない
  - 途中で抜けた学習は完了扱いにならず、途中で抜けた取組は成績にも報酬にも入らない
  - ルートガード（設計書「16.」）の扱いも変えない

## 検討した代替案

### 確認なしで直接タイトルへ戻す

操作は1回で済むが、押し間違いで進行中の取組を捨てることになる。
一方向に進む画面の中に、取り消せない操作を確認なしで置きたくない。

### 行き先をマップだけにする

ステージから見て自然な戻り先はマップだが、
「トップページに戻りたい」という要求はマップでは満たせない。
マップにもタイトルへの導線がないため、結局ブラウザの戻る操作に頼ることになる。

### `GameShell` に共通の離脱導線を持たせる

全画面で同じ位置に出せるが、マップや図鑑にはすでに戻る導線がある。
出す必要があるのは、導線が途中で途切れる学習と取組の2画面だけである。

共通の外枠に持たせると、画面ごとに文言を変える必要が出て、外枠が画面の事情を知ることになる。
