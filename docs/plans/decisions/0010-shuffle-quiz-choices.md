# ADR-0010: 選択肢の並びを取組の開始時にランダムにする

状態: 採用
日付: 2026-08-29

## 背景

マスターデータ `src/data/quizzes.ts` の全35問で、正解が選択肢配列の先頭に置かれていた。

取組画面は `quiz.choices` を配列の順に描画していたため、
表示上も正解が常に1番目に出ていた。

内容を読まずに「1番目を選ぶ」だけで全問正解できる。
これは[PRD](../../sumo-quest-prd.md)が求める学習の成立を損なう。

[設計書](../../sumo-quest-design.md)「8. データモデル」は、
正解を選択肢番号ではなく選択肢IDで持ち「並べ替えに耐えられるようにする」と定めている。
並べ替えに耐える構造はあったが、実際に並べ替える処理がなかった。

## 決定

**選択肢の並びは、取組の開始時に一度だけランダムにする。**

- 並べ替えは `src/lib/shuffle.ts` の純粋関数が行い、乱数源を引数で受け取る
- `BattleScene` が初期化時に全問分を並べ替え、その並びを取組の最後まで保つ
- マスターデータの並びは変更しない。`correctChoiceId` が正解の唯一の根拠である

## 理由

並べ替えを実行時に行うのは、データ側で正解の位置を散らす案では
問題を1問足すたびに同じ配慮が必要になり、抜けても機械的に気付けないためである。
実行時に並べ替えれば、データの並びが何であれ表示は偏らない。

取組の開始時に一度だけ行うのは、描画のたびに並べ替えると
回答した直後に選択肢が入れ替わり、押したものと解説が結び付かなくなるためである。

再挑戦のたびに並びが変わる。同じ問題を繰り返しても位置の記憶では答えられない。

乱数源を引数にしたのは、テストで並びを固定するためである。
既定は `Math.random` で、呼び出し側は通常なにも渡さない。

## 影響

- `src/lib/shuffle.ts` を追加する
- `BattleScene` は受け取った `quizzes` をそのまま描画せず、並べ替えた写しを描画する
- 選択肢の位置を前提にしたテストは、表示（ラベル）で選ぶ形に改める
- E2Eテストは以前からコンテンツデータの `correctChoiceId` を引いて選んでいるため、変更は不要
- 設計書の記述は変更しない。「並べ替えに耐えられるようにする」の実施にあたる

## 検討した代替案

**マスターデータ側で正解の位置を散らす。**
実行時の処理が不要になる一方、毎回同じ並びになるため、
繰り返し挑戦するプレイヤーには位置の記憶が効いてしまう。
新しい問題を追加するときの配慮も人手に残る。

**問題の出題順もランダムにする。**
ステージ内の問題は易しい順に並べており、この順序には意図がある。
今回の問題は選択肢の位置であり、出題順は変更しない。
